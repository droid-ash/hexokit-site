HexoKit — 12 landing-page iterations × 2 variations

Same facts, twelve structures. Each mockup copies the measured structure of one well-marketed tool site that has nothing to do with terminals — type scale, spacing, buttons, containers, section rhythm — and pairs it with the beat of the HexoKit story it is structurally best at telling. Every page works in light and dark and down to 400px. Copy follows content-spine.md. Each iteration comes in two variations: A uses the real product screenshots; B replaces every one with a minimal schematic drawn in HTML — the real layout and chrome, three to six elements, big type — so the visual explains the product instead of proving it exists. A and B are otherwise identical, so the comparison is purely visual density.

What is copied is structure and measurement — layout, type scale, spacing, component geometry, section order — read off each site's live DOM on 2026-09-13 (references/measurements.json). What is not copied is anyone's brand: no logos, custom typefaces, illustrations, photographs, colours-as-identity, or copy. Free faces stand in for proprietary ones (Geist for CursorGothic, Instrument Serif for Domaine, Space Grotesk for f37 Analog, Nunito for RoundHog, DM Sans for Diatype, Outfit for Geomanist). All twelve use HexoKit's amber/teal accents and its own product screenshots. B files are generated from A by python3 make-b.py; regenerate all thumbnails with node shoot.mjs from the repo root.
