01

HexoKit is a console for your tmux, and a layer above the agent you already use.

Cockpit for the agent era.

Your tmux, in the browser and on your phone. Every session and pane is a live terminal, in a sidebar, from your desk or your couch. It is the modern, terminal-native answer to the old server web-console: nothing to configure, no database, state read straight from tmux.

What makes it so good right now is what tends to run in those panes: coding agents, many at once. HexoKit never wraps the agent. A pane is just a pane. It is equally a build, a REPL, an ssh session, htop. The agent is one of the things you run, not the thing HexoKit is. When the agent tooling churns underneath you, and it does, monthly, the terminal layer stays put.

It is not another coding agent, and it does not want to be. The coding agent writes the code; HexoKit handles everything around it. Capturing the idea, writing the plan, isolating the work, watching the session, and pinging your phone when the agent is waiting on you.

Who it is for

This is workflow infrastructure, and infrastructure earns its weight at scale. If you are just getting started with AI coding, you do not need it yet. Learn to collaborate with a single agent first, and reach for HexoKit when the workflow around that agent starts to hurt.

It starts to pay off when you work in large repositories, run more than one agent or more than one feature in parallel, want a written plan before any code is written, and want that plan, the backlog and the cost trail stored in git as plain files. If none of that is true yet, the toolkit is overkill, and saying so is part of the point.

Plan before you code

Letting an agent code straight from a one-line prompt produces predictable garbage. fab-kit's six stages exist because of that. Intake, apply, review, hydrate, ship, review-PR. The intake stage cannot be skipped. Forcing it adds ten minutes and saves two hours of rework.

The agent scores its own assumptions. Four questions per decision: how clear was the signal, how reversible is it, can the agent actually know this, how many readings are there. The change starts at 5.0 and every weak decision costs points. Under 3.0 the gate closes and the pipeline tells you what to clarify. A single risky guess stays visible. It is never averaged away.

$ fab score --check-gate 7ajq
confidence 2.6 / 5.0 · gate 3.0 · blocked
  1 unresolved: auth provider — run /fab-clarify
$ fab score --check-gate 7ajq
confidence 3.4 / 5.0 · gate 3.0 · pass

One agent watches the others

rk operator opens a coordinator you talk to. It watches the fleet, starts the next change, unblocks a stuck one, and escalates to your phone when something needs you. rk riff -N 3 gives three agents three worktrees and three windows with one command. One shortcut and its console slides down over whatever you are looking at. Your pane never moves. Pin three agents and the dev server into a board; one dot per window says working, waiting or idle.

Serve the dashboard over Tailscale and the same board is on your phone, with a key bar for tab, ctrl and arrows. Switch on rk gui and the agent gets a desktop of its own in a tile beside your terminals: it opens apps, clicks, types and takes screenshots through rk gui exec, shot, click and type, and you watch. Off by default, and yours to switch off.

What it refuses to do

  • No agent wrapperIt reads no agent's output and speaks no agent's protocol. That is what makes it outlive whichever agent you run.
  • No databaseState is read from tmux and the filesystem on every request. Nothing to migrate, nothing to sync, nothing to lose.
  • No SDK lock-inPlain markdown prompts and a CLI. Switch agents tomorrow, keep the toolkit.
  • No proprietary formatsEvery plan, backlog and cost report is markdown, YAML or JSON you can cat, grep and git diff.
  • No telemetry without a flagtu is opt-in observability for your own costs. Nothing phones home.
Install HexoKit

Six small tools, one job each

HexoKit is the base. Each tool does one thing and exposes a CLI. They share no daemon, no SDK, no database; they compose through files. Drop any one and the others keep working.

fab-kitA plan before any agent writes code. /fab-new
wtThrowaway git worktrees, one per change. wt create
ideaCatch an idea without breaking flow. idea add
tuWhat your AI coding sessions cost. tu --watch
hopJump to any of your repos. hop --all pull
shllInstalls and updates the whole set. shll setup agent

One line, then you are in

$ curl -fsSL hexokit.com/install | sh
$ rk daemon start && open http://localhost:3000
$ rk tutorial

Needs tmux 3.4 or newer. Run rk doctor if anything looks wrong. MIT, all seven repos.
