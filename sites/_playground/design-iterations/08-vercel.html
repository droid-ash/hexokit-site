01 · PLAN

A plan before any code.

fab-kit puts an intake stage in front of every change. The agent scores each assumption. Four questions per decision: how clear was the signal, how reversible is it, can the agent know this, how many readings are there. The change starts at 5.0 and every weak decision costs points. Under 3.0 the gate closes and the pipeline tells you what to clarify.

fab score
$ fab score --check-gate 7ajq
confidence 2.6 / 5.0 · gate 3.0
blocked — 1 unresolved
run /fab-clarify

$ fab score --check-gate 7ajq
confidence 3.4 / 5.0 · gate 3.0 · pass
02 · BUILD

One command per parallel agent.

rk riff gives an agent its own git worktree and tmux window. -N 3 starts three. The operator watches the fleet and pings your phone when it needs you.

rk riff
$ rk riff --skill /fab-fff -N 3
→ worktree ../repo.worktrees/swift-fox
→ worktree ../repo.worktrees/calm-heron
→ worktree ../repo.worktrees/amber-tern

$ rk operator
03 · SHIP

Review in a fresh sub-agent, then a PR.

Review loops back to apply up to three times. Ship opens the draft PR. Review-PR triages the bot's comments. What the change learned lands in docs/memory, in git.

.status.yaml
intake     done
apply      done
review     done  2 cycles
hydrate    done  docs/memory +3
ship       done  PR #967 draft
review-pr  active
